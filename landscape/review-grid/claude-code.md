# Claude Code: lesson 6 review grid (how review findings are graded and filtered)

Scope: lesson 6 only, the quality of a review: how findings are graded, what keeps weak ones off the PR, what the reviewer reads
for guidance, what each finding must show, how a repeat review behaves, how a person says a finding is wrong, how noise is
counted, and whether the reviewer states a verdict. Left out on purpose: what triggers a review and who fixes the PR afterwards
(lesson 4, see `landscape/routing-grid/claude-code.md`), how work is checked before the PR (lesson 3, see
`landscape/verify-grid/claude-code.md`), billing beyond what bears on review volume, and permission or sandbox design. Every
filled cell is a paraphrase of a first-party page, with its URL and the date I fetched it (**2026-11-11**). The two files above
were a starting list; every page used here was fetched again.

Names are Anthropic's own (Code Review, `REVIEW.md`, `/code-review`, ultrareview), not canonical. A cell says `not in their docs`
only after naming the pages checked, and that wording means only that those pages do not say it; it is not a claim about the
product.

Method: fetched the docs index (https://code.claude.com/docs/llms.txt, 2026-11-11), listed every page that could touch review,
severity, guidance files, CI review, security review, analytics or memory, and downloaded each as raw Markdown (the `.md` form of
its URL) with `curl`. The pages in the first block of "Pages read" were read in full. The plugin README and command file come
from the first-party `anthropics/claude-plugins-official` repository on GitHub (raw files, read in full). Those two files are a
snapshot of the repository's main branch on the fetch date; the docs page for the GitHub Action says it "runs the same plugin" as
the one used there, so the plugin column is about that plugin.

Surfaces: **Code Review service** (managed, Team and Enterprise, GitHub pull requests), **local `/code-review`** (a bundled
command run in a session, any plan), **`code-review` plugin via the GitHub Action** (your own CI runs the plugin's command),
and **ultrareview** (a deeper cloud review started from a session).

([plugin README](https://github.com/anthropics/claude-plugins-official/blob/main/plugins/code-review/README.md), 2026-11-11) | Not graded in the pages read; it says every reported finding was independently reproduced and verified. No built-in count cap: not in their docs (checked: Code Review, Customize, Read and request reviews). A later automatic review posts fewer nits and pre-existing findings and says in the review body how many it left out. ([Customize](https://code.claude.com/docs/en/code-review-customize.md), [Read and request reviews](https://code.claude.com/docs/en/code-review-pull-requests.md), 2026-11-11) | `--max-findings <n>` (or `all`, or `default`) replaces the review's usual limit; where findings go through the findings tool the limit is 32. ([Review locally](https://code.claude.com/docs/en/code-review-local), 2026-11-11) | Threshold: issues scoring under 80 are dropped; the README says to edit the number in the command file to change it. A review works from reading the diff and surrounding code and does not build or run the code. ([Code Review](https://code.claude.com/docs/en/code-review.md), 2026-11-11) | Not in their docs as a separate pass (checked: Review locally; the command's instructions are built in, so there is no file to read, per that page). ([Review locally](https://code.claude.com/docs/en/code-review-local), 2026-11-11) | Yes: bug candidates from two agents each go to a validating agent (Opus for bugs, Sonnet for guidance-file violations) and anything not validated is dropped; the README also describes the 0-100 scoring step. The command file lists what to skip, then asks to draft the comment list before posting. ([command file](https://github.com/anthropics/claude-plugins-official/blob/main/plugins/code-review/commands/code-review.md), 2026-11-11) | Yes: each finding is independently reproduced and verified by a multi-agent fleet in a cloud sandbox. A run takes roughly 5 to 15 minutes. ([Ultrareview](https://code.claude.com/docs/en/ultrareview.md), 2026-11-11) |

([Read and request reviews](https://code.claude.com/docs/en/code-review-pull-requests.md), 2026-11-11) | Not in their docs (checked: Review locally). ([Review locally](https://code.claude.com/docs/en/code-review-local), 2026-11-11) | Yes, a filter: "pre-existing issues" are on the do-not-flag list, the bug agents are told to look only inside changed code, and a separate agent reads git blame and history for context. ([command file](https://github.com/anthropics/claude-plugins-official/blob/main/plugins/code-review/commands/code-review.md), [README](https://github.com/anthropics/claude-plugins-official/blob/main/plugins/code-review/README.md), 2026-11-11) | Not in their docs (checked: Ultrareview page). | **Repo guidance files it reads, and how it is told what to ignore** | `CLAUDE.md` (repo root plus parent directories of each changed file, and a subdirectory one when the PR changes a file under it) read as project context; a violation becomes a finding. `REVIEW.md` for review only: root file, plus subdirectory files on a protected branch (not under names such as `tests`, `generated`, `vendor`). `REVIEW.md` can include up to eight other files with a line holding only `@name` (root-level files, or a `.claude/skills/<folder>/SKILL.md`). Read from the base or default branch, never from the PR's own changes; exclusions, severity lowering and nit caps are honored only from a protected branch. "Ignore" is prose in `REVIEW.md` (the example has a "Do not report" list: CI-enforced checks, generated files, lockfiles). ([Customize](https://code.claude.com/docs/en/code-review-customize.md), 2026-11-11) | Reads `CLAUDE.md`, including in `-p` runs; does not read `REVIEW.md`. Put guidance for both in `CLAUDE.md`. ([Review locally](https://code.claude.com/docs/en/code-review-local), [Customize](https://code.claude.com/docs/en/code-review-customize.md), [Memory](https://code.claude.com/docs/en/memory.md), 2026-11-11) | `CLAUDE.md` files: the root one plus those in directories of modified files; two agents audit compliance and only files sharing a path with the changed file or its parents count. `REVIEW.md`: not in the README or command file. Ignore list is inside the command file (linters' territory, pedantic nitpicks, code with an explicit lint-ignore comment) and is edited there. ([command file](https://github.com/anthropics/claude-plugins-official/blob/main/plugins/code-review/commands/code-review.md), [README](https://github.com/anthropics/claude-plugins-official/blob/main/plugins/code-review/README.md), 2026-11-11) | Free-text note after the command is attached to the review; guidance files: not in their docs (checked: Ultrareview page, Review locally). ([Ultrareview](https://code.claude.com/docs/en/ultrareview.md), 2026-11-11) |

## Findings worth carrying into the lesson

- Four reviewers share one product name. The managed service grades by severity with a first-class "Pre-existing" class; the plugin grades by 0-100 confidence with an 80 cutoff and drops pre-existing issues. Different filters, same goal. ([Read and request reviews](https://code.claude.com/docs/en/code-review-pull-requests.md), [plugin README](https://github.com/anthropics/claude-plugins-official/blob/main/plugins/code-review/README.md), 2026-11-11)
- Guidance is two files with different readers: `CLAUDE.md` (both the service and local command) and `REVIEW.md` (the service only). "Ignore" and caps are prose, honored only from a protected base branch. ([Customize](https://code.claude.com/docs/en/code-review-customize.md), 2026-11-11)
- Teaching is manual: resolve the thread, reply, then write a rule into `REVIEW.md`. The docs describe no automatic learning from reactions. ([Read and request reviews](https://code.claude.com/docs/en/code-review-pull-requests.md), 2026-11-11)
- Noise is counted through acceptance-style signals (comments auto-resolved because the issue was fixed, findings by severity), not a stated false-positive rate. ([Code Review costs](https://code.claude.com/docs/en/code-review-costs.md), 2026-11-11)
- The verdict is deliberately absent: neutral check, no approval, and an exposed severity count for people who want to build a gate. ([Code Review](https://code.claude.com/docs/en/code-review.md), 2026-11-11)
- Re-review is explicit about what it left out (counts in the review body), which makes the "no repeat" behavior auditable. ([Read and request reviews](https://code.claude.com/docs/en/code-review-pull-requests.md), 2026-11-11)
