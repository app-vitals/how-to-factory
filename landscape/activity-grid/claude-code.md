# Claude Code: activity grid

Scope: how Claude Code shows what the agent is doing and has done: current and queued work, status, the reason an item waits,
an activity log, history, the link from an item to its PR, why the agent did something, cost, and whether it works for one local
agent without a hosted account. Left out on purpose: how work is planned, built, verified or reviewed (lessons 1 to 4). Every
filled cell is a paraphrase of a first-party code.claude.com page, with its URL and the date I fetched it (**2026-10-30**). Names
are Anthropic's own (agent view, Projects, scheduled tasks, formerly routines), not canonical. A cell says `not documented` only
after naming the pages checked. "Not documented" means not in their docs, not that the product cannot do it.

Starting notes: `landscape/field-grid/claude-code.md` and `landscape/routing-grid/claude-code.md` were a starting list only. Both
predate this lesson's dimensions, and the docs have moved since (agent view, Projects and the scheduled-tasks rename are newer than
the routing grid), so every page used here was fetched again.

Method: fetched the docs index (https://code.claude.com/docs/llms.txt, 2026-10-30), listed the pages that could touch sessions,
background work, scheduling, cost, telemetry and PR display, and fetched each as Markdown (`<url>.md`). Every page under "Pages
read" was read in full from the downloaded copy, and every `not documented` cell was checked against the whole of the pages named
in it. Reading was split across several helper readers who each returned a per-page summary; I assembled the grid from those
summaries and spot-checked the page copies for the retention numbers and status names. Honest limit: pages not under "Pages read"
were judged from the index only (see "Ruled out").

## The grid

Surfaces: **Interactive CLI** (a terminal session: task list, transcript, footer, `/usage`), **Agent view** (`claude agents`, the
CLI's screen for many background sessions on one machine; marked research preview), **Desktop** (the Code tab of the desktop app,
local sessions plus its Scheduled page), **Cloud** (claude.ai/code cloud sessions, Projects, and cloud scheduled tasks), **SDK and
telemetry** (the Agent SDK's messages and cost fields, plus OpenTelemetry export). No single surface covers every dimension.

## Findings worth carrying into the lesson

- The single closest view to "one list of all my agent's work" is agent view: one row per background session with state, a
  one-line activity, a stated reason when it needs you, and a PR link. It is local, per machine, and still a research preview.
  ([Agent view](https://code.claude.com/docs/en/agent-view.md), 2026-10-30)
- The unit of tracking is the session, not the task. The pages checked show no task record with its own status, reason and PR
  that survives across sessions; the to-do list is per session (or shared by an id) and empty on some models by default.
  ([Interactive mode](https://code.claude.com/docs/en/interactive-mode.md), [Track todos](https://code.claude.com/docs/en/agent-sdk/todo-tracking.md), 2026-10-30)
- Stated reasons are strongest where something is scheduled or unattended: scheduled-task runs name why they were skipped or
  failed, and agent view names what a session is waiting for. ([Scheduled tasks](https://code.claude.com/docs/en/routines.md), [Agent view](https://code.claude.com/docs/en/agent-view.md), 2026-10-30)
- The PR link is a display feature (badge, row link, card button) driven by what the session did, not a stored field; the status
  line stops reporting it after the PR merges. ([Customize your status line](https://code.claude.com/docs/en/statusline.md), [Agent view](https://code.claude.com/docs/en/agent-view.md), 2026-10-30)
- Cost is available per session and per call as an estimate, and per run only through telemetry you collect yourself; the agent
  view rows and Desktop sessions show none. ([Manage costs](https://code.claude.com/docs/en/costs.md), [Monitoring](https://code.claude.com/docs/en/monitoring-usage.md), 2026-10-30)
- Retention differs by artefact and is mostly a single local setting (30 days by default for transcripts), with shorter
  clocks on loops (7 days), shell-job rows (about 5 minutes) and idle agent-view processes (about 1 hour).
  ([Manage sessions](https://code.claude.com/docs/en/sessions.md), [Agent view](https://code.claude.com/docs/en/agent-view.md), [Scheduled loops](https://code.claude.com/docs/en/scheduled-tasks.md), 2026-10-30)
- Whether you need an account depends on the surface: terminal views, agent view and the SDK run on one machine; cloud sessions,
  Projects and cloud scheduled tasks need a claude.ai login and GitHub. ([Agent view](https://code.claude.com/docs/en/agent-view.md), [Cloud sessions](https://code.claude.com/docs/en/claude-code-on-the-web.md), 2026-10-30)
- Two pages disagree on whether a project thread reads repository settings: the cloud-session page says a single-repo cloud
  session reads `.claude/settings.json`, the Projects page says threads do not load it. ([Cloud sessions](https://code.claude.com/docs/en/claude-code-on-the-web.md), [Projects](https://code.claude.com/docs/en/claude-projects.md), 2026-10-30)

## Ruled out (why)

- **Claude Tag and Claude Code in Slack** (`/claude-tag.md`, `/slack.md`): judged from index titles only, not fetched this round; they
  concern delegating work from chat, and the routing grid already covered them. A gap, not a finding.
- **Agent SDK observability and session-storage pages**: judged from index titles; they concern exporting traces and mirroring
  transcripts, the same ground as the Monitoring and Work with sessions pages read. A gap, not a finding.
- **Analytics dashboard (`/analytics.md`) and gateway pages**: org-level usage reporting, not a view of one agent's work; judged from
  the index only.
- **Changelog and the weekly "what's new" pages**: not searched; later releases may add activity features. A gap, not a finding.
- **Hooks, channels, deep links, artifacts, cross-session messaging**: judged from index titles; they push events into or out of a
  session rather than show activity. Artifacts could present results as a page; not read.
- **Code Review pages** (`/code-review*.md`): covered in the routing grid (2026-10-28); they describe review triggers, not an
  activity view.
- **Self-hosted environments pages**: setup and identity for cloud sessions on your own infrastructure; judged from the index only.
- **Troubleshooting, installation, authentication, settings reference**: setup, not activity views; judged from the index only.
