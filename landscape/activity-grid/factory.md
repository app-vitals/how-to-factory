# Factory (Droids / Missions): lesson 5 activity grid

Scope: lesson 5 only, how Factory shows what the agent is doing and has done: work items, status, reasons for waiting,
logs, history, links to PRs, the "why" behind an action, cost, and whether it works without a hosted account. Left out on
purpose: how work is planned, verified or reviewed (lessons 1 to 4). Every filled cell is a paraphrase of a first-party
docs.factory.com page, with its URL and the date I fetched it (**2026-10-30**). Names are Factory's own, not canonical. A
cell says `not documented` only after naming the pages checked. "Not documented" means not in their docs, not that the
product cannot do it.

Starting notes: `landscape/field-grid/factory.md` (2026-10-23) and `landscape/routing-grid/factory.md` (2026-10-28) were a
starting list only. The index has moved since: the automation pages now live under `/automations/` (the routing grid cites
older `/software-factory/` URLs), so every page used here was fetched again.

Method: fetched the docs index (https://docs.factory.com/llms.txt, 2026-10-30), listed the pages that could show work in
progress, history, cost or the reasoning behind an action, and downloaded each as raw Markdown (`<url>.md`) with `curl`.
Short pages were read whole. For long pages (Custom Automations, Sessions API, CLI Reference, Droid Exec, Telemetry) I
read the sections on runs, status, history, cost and sessions and searched the rest by keyword; a "not documented" answer
on those pages rests on that keyword search plus the sections read, not on every line.

**Sessions** (the session list in the app and CLI, plus the Sessions API), **Analytics** (organization dashboards and

## Findings worth carrying into the lesson

- Factory spreads activity over several places rather than one queue-and-log page: Mission Control for a Mission, the Events feed for automations, the issue or Slack thread for delegations, the session list for everything else. No page in the docs describes a single view across all of them. (pages in the cells above, 2026-10-30)
- The clearest stated-reason surface is the Automations Events feed: skipped deliveries and automatic pauses each name a cause. ([Custom Automations](https://docs.factory.com/automations/custom.md), 2026-10-30)
- The clearest PR link is the per-session "artifacts" list in the Sessions API (pull request, provider, action such as merge). ([Sessions API](https://docs.factory.com/api-reference/sessions.md), 2026-10-30)
- Cost per item exists at session level (credits in the API, `/cost` in the CLI) and at mission level (top bar). Per run for automations and per delegation: not in their docs.
- Retention is stated in three places only: 30 days for webhook deliveries, 7 days of inactivity for Slack code channels, and an unspecified "retention period" for deleted sessions.
