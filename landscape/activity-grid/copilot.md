# GitHub Copilot: activity grid

Scope: how Copilot shows what the agent is doing and has done: current and queued work, status, the reason an item waits,
an activity log, history, the link from an item to its PR, why the agent did something, cost, and whether it works for one
local agent without a hosted account. Left out on purpose: how work is planned, built, verified or reviewed (lessons 1 to 4).
Every filled cell is a paraphrase of a first-party docs.github.com page, with its URL and the date I fetched it
(**2026-10-30**). The notes in `landscape/field-grid/copilot.md` and `landscape/routing-grid/copilot.md` (both for the same
product) were a starting list; every page used here was fetched again.

Names are GitHub's own, not canonical. A cell says `not documented` only after naming the pages checked. "Not documented"
means not in their docs, not that the product cannot do it.

Method: fetched the docs index (https://docs.github.com/llms.txt, 2026-10-30), which lists only a few Copilot pages, so I
also read the section index pages in their Markdown form (append `.md` to a docs URL): the cloud agent how-to index
(https://docs.github.com/en/copilot/how-tos/use-copilot-agents/cloud-agent), the agents how-to index
(https://docs.github.com/en/copilot/how-tos/use-copilot-agents), the agent capabilities concepts index
(https://docs.github.com/en/copilot/concepts/agent-capabilities) and the cloud agent tutorials index
(https://docs.github.com/en/copilot/tutorials/cloud-agent), all fetched 2026-10-30. From those I listed the pages that could
touch sessions, tasks, logs, usage, retention and automations, and fetched each as raw Markdown with curl. The pages marked
"full" under "Pages read" were read top to bottom; the pages marked "searched" were read by searching for session, log, status,
usage, credit, history, archive, retention and queue terms and reading the matching sections, so a `not documented` that rests on
one of those pages rests on those searches, not a line-by-line read.

## The grid

Surfaces: **Cloud sessions on GitHub** (the cloud agent started from the Copilot home page, the repository Agents tab or panel,
an assigned issue, a PR comment, GitHub Mobile or the `gh` CLI; shown in the session list, the session log and the PR),
**Automations** (cloud agent runs started by a schedule, a repository event or the API with a saved prompt; shown in the
repository's Automations pane), **Copilot CLI** (the terminal agent, run on the person's own machine by default), **Agent tasks API**
(a public-preview REST API for starting and listing cloud agent tasks, for people who build their own dashboard).

## Findings worth carrying into the lesson

- The unit Copilot shows is the session, not the work item. The strongest views are the session log (live reasoning and tools),
  the PR timeline event that links to it, and the commit-message link back to the log. Queue-style views for waiting issues are
  not in the pages read. ([Managing agent sessions](https://docs.github.com/en/copilot/how-tos/copilot-on-github/use-copilot-agents/manage-and-track-agents.md), 2026-10-30)
- The only complete status vocabulary is in the preview REST API (`queued`, `in_progress`, `completed`, `failed`, `idle`,
  `waiting_for_user`, `timed_out`, `cancelled`); the web session list's own status names are not documented in the pages read.
  ([REST API: agent tasks](https://docs.github.com/en/rest/agent-tasks/agent-tasks.md), 2026-10-30)
- Waiting reasons live in the product's side effects, not in an item view: a firewall warning in the PR, an `Approve and run
  workflows` button, a one-hour timeout. ([Troubleshooting cloud agent](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/cloud-agent/troubleshoot-cloud-agent.md), 2026-10-30)
- Cost is shown at the right grain in two places: per session in the API (`usage`) and the CLI (`/usage`), and per automation in
  the Automations pane, with per-run, daily, weekly and monthly caps. ([Creating automations](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/cloud-agent/create-automations.md), 2026-10-30)
- Sessions are open by default for Actions-run sessions and automations: anyone with read access to the repository can see the
  prompt, the log and the PR. Sandbox and local sessions are private to their owner until shared.
  ([About session data](https://docs.github.com/en/copilot/concepts/security-governance-and-network-settings/session-data.md), 2026-10-30)
- Two pages leave the retention story unclear: one says an Actions session's log remains available, another gives 28 days for
  its chat data. ([About session data](https://docs.github.com/en/copilot/concepts/security-governance-and-network-settings/session-data.md), [Copilot on GitHub.com](https://docs.github.com/en/copilot/concepts/copilot-surfaces/copilot-on-github.md), 2026-10-30)
- Only the CLI is documented as keeping the record on the person's own machine (`~/.copilot/session-state/`); the other surfaces
  are cloud-side and use a GitHub account. ([About session data](https://docs.github.com/en/copilot/concepts/security-governance-and-network-settings/session-data.md), 2026-10-30)

  Azure Boards, Raycast)**: other places to start a task; not read.
- **Copilot code review**: covered in the lesson 4 routing grid; it is a reviewer, not an activity view for agent work.
- **Changelog / release notes**: not searched; newer activity features might be listed there. A gap, not a finding.
- **REST endpoints for sessions beyond the agent tasks page, and GitHub Mobile screenshots**: not read; the log text API, if
  there is one, would sit there.
