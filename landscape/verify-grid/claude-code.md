# Claude Code: verification grid

Scope: how Claude Code verifies work, meaning what checks run, who decides a task is done, whether the product runs the app
itself, what keeps it going, and what evidence the person sees. Left out on purpose: how plans are made (see
`landscape/plan-grid/` and `landscape/field-grid/claude-code.md`), permission and sandbox design, and review policy beyond
what it says about verifying. Every filled cell is a paraphrase of a first-party page, with its URL and the date I fetched it
(**2026-10-21**). Names are Anthropic's own (hooks, `/goal`, Code Review, ultrareview, dynamic workflows), not canonical.
Several surfaces are used because no single one covers every dimension; each row names its surface. Claude Code is mostly a
toolkit: where a page says "write a hook" or "ask in the prompt", the cell says the check is the person's, not built in.

Method: fetched the docs index (https://code.claude.com/docs/llms.txt, 2026-10-21), listed every page that could touch
verification (best practices, hooks guide and reference, `/goal`, subagents, headless, GitHub Actions, Code Review and its
settings pages, `/code-review`, ultrareview, cloud sessions and auto-fix, skills, commands, checkpointing, Chrome, computer
use, dynamic workflows, agent teams), then fetched the Markdown (`<url>.md`) of each. The fetch tool passes a page through a
small model and returns its answer, not raw text. Some pages came back as long, page-like text and some as short extractions
(skills, commands, sub-agents, the hooks reference); I cannot certify any of it as verbatim, so quoted phrases are short and a
claim resting on a thinly returned page is marked "(summary)". Where two reads disagreed I say so (see the Stop hook block cap).
Started from `landscape/field-grid/claude-code.md` (2026-10-13) but every page was fetched again; its notes were not carried
over unchecked, and one of them is corrected below (SubagentStop).

## Not documented (with pages checked)

- A built-in test, lint or typecheck step in an interactive session, or any list of what "the relevant checks" are: best-practices,
  hooks-guide, headless, skills, commands. The product leaves it to the prompt, skills, hooks or CLAUDE.md.
- A guard against an agent weakening or deleting tests (any surface): best-practices, hooks-guide, goal, checkpointing,
  code-review-customize, sub-agents, agent-teams. Only wording a person adds (a `/goal` constraint, a protected-path hook) is shown.
- Coverage thresholds or test-speed budgets: best-practices, code-review, code-review-customize, goal, headless, github-actions.
  Limits that exist bound turns, agents, time or cost, not coverage.
- Whether GitHub Actions or Code Review results are required checks, and any branch-protection recipe beyond the conversation-resolution
  note and the scripted severity-count gate: github-actions, code-review, code-review-pull-requests, code-review-customize.
- What the cloud session or `claude -p` runs without a prompt, and any built-in verify-and-retry loop outside `/goal`, `Stop` hooks,
  workflows and auto-fix: claude-code-on-the-web, headless, goal.
- A pass/fail rule or recording for Computer use, and a pass/fail rule for Chrome: computer-use, chrome.
- Per-task test lists generated by the product: best-practices, goal, workflows, agent-teams.
- The exact `Stop` hook consecutive-block cap and its variable name: hooks-guide says eight and `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`; a
  summarised read of hooks said five and `CLAUDE_CODE_MAX_STOP_HOOK_BLOCKS`; the env-vars read was truncated. Unresolved.
