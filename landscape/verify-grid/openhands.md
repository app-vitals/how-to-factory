# OpenHands: lesson 3 verification grid

Scope: lesson 3 only, the step where finished work is checked before it counts as done: what runs, who calls it done, whether
the app is run, how the loop keeps going after a failure, how criteria become checks, test planning, CI and branch gating,
limits, protection against weakened tests, evidence shown to the person, and fixes after the PR is open. Left out on purpose:
how plans are made (lesson 2 plan grid), how tickets are picked (lesson 1 field grid), and review as a general activity (only
its role as a check on delivered work is used). Every filled cell is a paraphrase of a first-party docs.openhands.dev page,
with its URL and the date I fetched it (**2026-10-23**). The notes in `landscape/field-grid/openhands.md` (2026-10-13) were a
starting list only; every page used here was fetched again.

"Who decides done" uses exactly one of **Human**, **Human approves** or **Automated**, and only where a page states it.
Otherwise the cell says `not documented` and names the pages checked. Names are OpenHands' own, not canonical. Several
surfaces are used because no single one covers every dimension; a cell that depends on what the person types into the prompt
says so.

Method: fetched the docs index (https://docs.openhands.dev/llms.txt, 2026-10-23), listed every page on testing, QA, critic,
goal loop, review, automations, issue-to-PR, hooks, security and recording, and fetched each as a raw-Markdown URL under
"Pages read". Honest limit: the fetch tool returns a condensed extraction of each page, not the raw text, and I asked it
targeted questions per page (what runs, who decides, caps, gating, weakened tests, evidence). I did not read any page
character by character, and a "not documented" answer rests on that tool saying the page lacked the topic. A few answers
were also hedged by the tool itself (for example, whether the critic runs tests); those cells say so. Release notes and the
Agent Canvas changelog were not searched (see "Ruled out"). The goal-loop slash command `/goal` mentioned in the 2026-10-13
notes was not re-confirmed this pass, so it is not used.

## The grid

Columns, left to right: WHAT RUNS; WHO DECIDES DONE; RUNS THE APP ITSELF; HOW IT KEEPS GOING; CRITERIA TURNED INTO CHECKS;
PER-TASK TEST PLANNING; CI OR BRANCH GATING; COVERAGE OR SPEED LIMITS; GUARD AGAINST WEAKENING TESTS; EVIDENCE SHOWN;
POST-PR AUTO-FIX. Each surface is one row below (the table is split into three blocks so it stays readable). One extra
dimension surfaced and is added as a column in Block C: WHO MAY CHANGE CODE (a permission split between roles).

## Findings worth carrying into the lesson

- The goal loop is the clearest documented "keep going until a check is shown to pass" mechanism: a separate judge reads real output, hands back a list of what is missing, and stops after a cap. ([Goal Completion Loop](https://docs.openhands.dev/sdk/guides/convo-goal.md), 2026-10-23)
- The critic scores a probability of success. It is a separate idea from a test run, and the pages call it experimental. ([Critic, SDK](https://docs.openhands.dev/sdk/guides/critic.md), 2026-10-23)
- QA is split from review on purpose: the QA agent runs the changed software and avoids running the suite, while the code reviewer reads the diff and does not run anything. ([Automated QA Testing](https://docs.openhands.dev/openhands/usage/use-cases/qa-changes.md), [Automated Code Review](https://docs.openhands.dev/openhands/usage/use-cases/code-review.md), 2026-10-23)
- In the Software Factory, "done" is automated: the merge step trusts independent statuses on the exact commit, and the reviewer cannot push code. That role split is the nearest thing to a structural guard in these pages. ([Software Factory](https://docs.openhands.dev/openhands/usage/use-cases/software-factory.md), 2026-10-23)
- No page checked gives a defence against weakened or deleted tests, a retry cap on the Issue to PR developer run, or recorded video of the running app. The only visual evidence mentioned for QA is screenshots; the session recording is an event log. (checked pages: see the cells above.)
- The Issue to PR page leans on human review of draft PRs, and the TODO page says the same. ([Issue to Pull Request](https://docs.openhands.dev/openhands/usage/agent-canvas/prebuilt/issue-to-pr.md), [TODO Management](https://docs.openhands.dev/sdk/guides/github-workflows/todo-management.md), 2026-10-23)
