# Devin: lesson 3 verification grid

Scope: lesson 3 only, the step where finished work is checked before it counts as done: what runs, who calls it done, whether
the app is run, how the loop keeps going after a failure, how criteria become checks, test planning, CI and branch gating,
limits, protection against weakened tests, evidence shown to the person, and fixes after the PR is open. Left out on purpose:
how plans are made (lesson 2 plan grid), how tickets are picked (lesson 1 field grid), and Devin Review as a general
reviewer (only its fix loop is used). Every filled cell is a paraphrase of a first-party docs.devin.ai page, with its URL and
the date I fetched it (**2026-10-21**). The verify notes in `landscape/field-grid/devin.md` (2026-10-13) were a starting
list only; every page used here was fetched again.

"Who decides done" uses exactly one of **Human**, **Human approves** or **Automated**, and only where a page states it.
Otherwise the cell says `not documented` and names the pages checked. Names are Devin's own, not canonical. Several
surfaces are used because no single one covers every dimension; a cell that depends on what the person types into the
prompt or playbook says so.

Method: fetched the docs index (https://docs.devin.ai/llms.txt, 2026-10-21), listed every Cloud, CLI and use-case page that
could touch testing, CI, review, recordings, playbooks, skills or auto-fix, and fetched each as raw-Markdown URLs under
"Pages read". Honest limit: the fetch tool returns a condensed extraction of each page, not the raw text, and I asked it
targeted questions per page (what runs, who decides, caps, branch protection, coverage, weakened tests). I did not read any
page character by character, and a "not documented" answer rests on that tool saying the page lacked the topic. The
CLI changelog and release notes were not searched for this lesson (see "Ruled out").

Columns, left to right: WHAT RUNS; WHO DECIDES DONE; RUNS THE APP ITSELF; HOW IT KEEPS GOING; CRITERIA TURNED INTO CHECKS;
PER-TASK TEST PLANNING; CI OR BRANCH GATING; COVERAGE OR SPEED LIMITS; GUARD AGAINST WEAKENING TESTS; EVIDENCE SHOWN;
POST-PR AUTO-FIX. Each surface is one row below (the table is split into three blocks so it stays readable).

## Findings worth carrying into the lesson

- The one place a person is told they will see proof is testing mode (a recorded video) and the Session Tools page; both are optional extras after CI and review, not a gate. ([Testing & Recordings](https://docs.devin.ai/work-with-devin/testing-and-recordings.md), 2026-10-21)
- No page gives a retry cap or stopping rule for Devin's own test loop, and none documents a defence against weakening tests. The only related text is a playbook example that forbids editing source files to ease testing. Coverage targets exist only as prompt or playbook examples. (checked pages: see the cells above.)
- "Done" is a human call in every place that states it (SDLC integration, Best Practices, CI-fix recipe), while Auto-Fix aims to leave PRs "ready to merge by the time you look at them" per the When-to-Use page. ([When to Use Devin](https://docs.devin.ai/essential-guidelines/when-to-use-devin.md), 2026-10-21)
