# GitHub Copilot: lesson 2 plan grid (spec to plan)

Scope: lesson 2 only, the step where a spec or request becomes a plan. Left out on purpose: test and verification planning
(verification lesson), how specs are written (intake lesson), standards files, estimates and model tiers, and bundling or
PR shaping. Every filled field is a paraphrase of a first-party page, with its URL and the date I fetched it
(**2026-10-19**). Nothing here is carried over from the 2026-10-13 notes in `lessons/README.md` or
`landscape/field-grid/copilot.md`; every page below was fetched again.

"Approval before work starts" uses exactly one of **Human**, **Human approves** or **Automated**, and only where a page
states it. Where a page does not, the cell says `not documented` and names the index pages checked. Names are GitHub's own,
not canonical. Several surfaces are used because no single one covers every column; each row names its surface.

Method: fetched the docs index (https://docs.github.com/en/copilot and the site-wide https://docs.github.com/llms.txt,
2026-10-19), listed every Copilot page that could touch planning, design before coding, code exploration, plan review or
approval, and turning a plan into tasks, then read those pages (as the docs' markdown source). Short pages were read in full;
for long reference-style pages only the planning-related sections were read, and the "Pages read" list says which. The rest
are under "Ruled out (why)".

## Ruled out (why)

Pages from the same index that I set aside for this lesson, from their index descriptions unless noted. None were opened (except where noted), so nothing in the grid relies on them.

- Prompt engineering, Managing context, Custom instructions, Prompt files, Repository indexing, Spaces and Copilot Memory (under https://docs.github.com/en/copilot/concepts/prompting-and-context/): context and instruction files, owned by a later lesson on standards. Repository indexing is about how search context is built, not how a plan is made.
- Custom agents and Agent skills pages (https://docs.github.com/en/copilot/concepts/agents/cloud-agent/about-custom-agents, https://docs.github.com/en/copilot/concepts/agents/about-agent-skills): how to author agents and skills. The planner example above is the only one that bears on planning.
- Copilot code review and Configuring code review pages: reviews code after it exists, not plans.
- Copilot automations, Dynamic workflows, GitHub Agentic Workflows, Scheduling prompts and the Copilot CLI automation pages: triggers and orchestration of recurring or scripted work; the rationale and approvals page that I read covers issue triage changes only, and says it does not cover pull requests or code, so it is not used in the grid.
- Integration pages for Slack, Teams, Jira, Linear and Azure Boards: ways to start the cloud agent. The research-plan-iterate page states that Jira, Linear and Azure Boards only support asking for a pull request directly, so they have no plan step.
- Models, auto model selection, bring your own key, AI model comparison and billing pages: model choice and cost, which belong to estimates and model tiers.
- Testing and verification tutorials (generate unit tests, fixing deadlocks, security review commands): verification planning belongs to the verification lesson.
- Enterprise, administration, security and governance, SDK, hooks, MCP, plugins, ACP, OpenTelemetry, responsible-use and troubleshooting sections: setup, policy and tooling, not planning behaviour.
- Estimates and sizes: the implementation planner template asks for small, medium and large labels; left out on purpose.
