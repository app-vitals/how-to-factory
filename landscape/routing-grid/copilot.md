# GitHub Copilot: lesson 4 PR routing grid

Scope: lesson 4 only, the step after a PR is open: what triggers a review, when it runs again, who may approve, whether the
product fixes its own PR, what limits exist, how the next action is chosen, where PR state lives, and the handoff to a
person. Left out on purpose: how plans are made, how tickets are picked, and how checks run before the PR (lessons 1 to 3).

## The grid

Surfaces: **Copilot code review** (the PR reviewer; Copilot is requested as a reviewer, automatically or by hand),
**Cloud agent PR follow-up** (`@copilot` comments, "Fix with Copilot", failing runs and merge conflicts on an existing PR),
**Automations** (cloud agent runs started by a schedule or a PR event with a saved prompt).

| Dimension | Copilot code review | Cloud agent PR follow-up | Automations |
| --- | --- | --- | --- |
| **What triggers it** | By default only when someone requests Copilot as a reviewer (sidebar, `gh pr create --reviewer @copilot`, `gh pr edit --add-reviewer @copilot`, or the REST API with `copilot-pull-request-reviewer[bot]`). Automatic reviews can be turned on per user, per repository or per organization (rulesets). Basic setting: PR opened, or a draft first marked ready. Options: review new pushes, review drafts. ([Code review concepts](https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/code-review.md), [Using code review](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/use-code-review.md), 2026-10-28) | A person with write access mentions `@copilot` in a PR comment, delegates review comments ("Fix with Copilot" or a batch), clicks "Fix with Copilot" on a merge conflict, or starts it from a failing Actions run page. Copilot ignores comments from people without write access and, once the PR is merged or closed, new mentions. ([Using cloud agent on GitHub](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/cloud-agent/use-cloud-agent-on-github.md), [Troubleshooting](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/cloud-agent/troubleshoot-cloud-agent.md), 2026-10-28) | Schedule (hourly, daily, weekly), issue created, PR opened, PR synchronized (new commits pushed). PR triggers take a search filter and a changed-files filter. Events from users without write access are ignored by default. Repositories must be private or internal. ([Copilot automations](https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/about-automations.md), [Creating automations](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/cloud-agent/create-automations.md), 2026-10-28) |
| **Re-review after new commits** | Not by default. Unless "Review new pushes" is on (user settings or a ruleset), Copilot reviews a PR once; a person can re-request with the re-request button. On a re-review Copilot may repeat comments that were resolved or downvoted. ([Code review concepts](https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/code-review.md), [Using code review](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/use-code-review.md), 2026-10-28) | Not a review. Copilot keeps context from earlier sessions on the same PR, so each new mention continues the work. ([Using cloud agent on GitHub](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/cloud-agent/use-cloud-agent-on-github.md), 2026-10-28) | The "PR synchronized" trigger runs the saved prompt on every push; what the run does is the author's prompt. ([Copilot automations](https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/about-automations.md), 2026-10-28) |
| **Who may approve, and does AI approval count** | Default: Copilot leaves a "Comment" review, which does not count toward required approvals. Every review carries an approval assessment in the overview comment, which on its own counts for nothing. When approvals are enabled (public preview; off by default; set at enterprise, organization and repository level) Copilot can submit an approving review that satisfies the required-approval rule like a teammate's. A repository setting can limit counting to PRs where every changed file matches given globs. If commits are pushed after Copilot approves, the approval is dismissed. ([Using code review](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/use-code-review.md), [Configuring code review](https://docs.github.com/en/copilot/how-tos/copilot-on-github/set-up-copilot/configure-code-review.md), 2026-10-28) | When a PR is written by Copilot, the requesting person's own approval does not count toward required approvals; another reviewer must approve. ([Review output from Copilot](https://docs.github.com/en/copilot/how-tos/copilot-on-github/use-copilot-agents/review-copilot-output.md), 2026-10-28) | PRs an automation opens are attributed to the person who created it, who cannot approve them. ([Copilot automations](https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/about-automations.md), 2026-10-28) |
| **Fixes its own PR: review comments** | Review comments carry suggested changes to apply with a click. "Fix with Copilot" on a comment hands it to the cloud agent, which either commits to the same PR or opens a new PR against the branch. Passing suggestions to the cloud agent is in public preview. The cloud agent also runs a code review pass on its own code before finishing its PR (on by default). ([Using code review](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/use-code-review.md), [Configuring agent settings](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/cloud-agent/configuring-agent-settings.md), 2026-10-28) | Yes, when asked: delegated review comments (from people or from Copilot code review) are implemented as commits to the branch or as a new PR. Batching comments into one review makes Copilot work on them together. Whether it starts on its own when a review arrives: not documented (checked: Using cloud agent on GitHub, Troubleshooting, Best practices). ([Using cloud agent on GitHub](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/cloud-agent/use-cloud-agent-on-github.md), [Best practices](https://docs.github.com/en/copilot/tutorials/cloud-agent/get-the-best-results.md), 2026-10-28) | The PR-synchronized trigger and the prompt decide; a template for fixing review comments: not documented (checked: Copilot automations, Creating automations). |
| **Fixes its own PR: red CI** | Not documented (checked: Code review concepts, Using code review). | Yes, when asked: on a failing Actions run page, start a session that investigates and pushes a fix to the branch. Workflows do not run on a Copilot push until a person with write access clicks "Approve and run workflows" (an admin can turn that approval off). Copilot validates with tests and linters in its own environment before pushing; a CI run starting a fix without a person: not documented (checked: Using cloud agent on GitHub, Troubleshooting, Configuring agent settings). ([Using cloud agent on GitHub](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/cloud-agent/use-cloud-agent-on-github.md), [Configuring agent settings](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/cloud-agent/configuring-agent-settings.md), 2026-10-28) | Not documented as a trigger (checked: Copilot automations: the triggers are schedule, issue created, PR opened, PR synchronized). Nightly "fix failing tests" on `main` is the page's own example. ([Copilot automations](https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/about-automations.md), 2026-10-28) |
| **Fixes its own PR: merge conflicts** | Not documented (checked: Code review concepts, Using code review). | Yes, when asked: "Fix with Copilot" in the merge box or an `@copilot` mention. It resolves the conflict, checks build, tests and linter, then asks the person for review. ([Using cloud agent on GitHub](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/cloud-agent/use-cloud-agent-on-github.md), 2026-10-28) | Not documented (checked: Copilot automations, Creating automations). |
| **Caps or limits on rounds** | A cap on review rounds per PR: not documented (checked: Code review concepts, Using code review, Configuring code review). Costs are per review (estimated ranges are given for Lite and Balanced), and reviews stop when the applicable budget is used up. ([Code review concepts](https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/code-review.md), 2026-10-28) | Each session runs at most 59 minutes (it can be set shorter). Copilot works on one branch at a time and opens one PR per task. A cap on follow-up rounds per PR: not documented (checked: Copilot on GitHub, Using cloud agent on GitHub, Troubleshooting). ([Copilot on GitHub](https://docs.github.com/en/copilot/concepts/copilot-surfaces/copilot-on-github.md), 2026-10-28) | Each run is a cloud agent session billed to the creator, so the session limit applies. Run-count or loop limits: not documented (checked: Copilot automations, Creating automations). ([Copilot automations](https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/about-automations.md), 2026-10-28) |
| **How it chooses the next action** | It does not choose; each review is a request or a configured trigger. Review effort (Lite or Balanced) is picked by a fixed order: set at request, then used earlier on this PR, then the requester's setting, then repository, then organization, then Balanced. ([Code review concepts](https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/code-review.md), 2026-10-28) | A person decides and says so in a comment, a button or a failing-run page. The best-practices page frames getting a PR mergeable as the same process whether a person or Copilot wrote it. ([Best practices](https://docs.github.com/en/copilot/tutorials/cloud-agent/get-the-best-results.md), 2026-10-28) | The trigger and the saved prompt, with the tools the author allowed. ([Copilot automations](https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/about-automations.md), 2026-10-28) |
| **Where PR state lives** | On the PR: review comments with severity labels, an overview comment with the approval assessment and the effort used per run, and the approval itself as a PR review. A review session is linked from the PR timeline. Rules for what counts live in repository, organization and enterprise settings and rulesets. ([Using code review](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/use-code-review.md), [Code review concepts](https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/code-review.md), 2026-10-28) | On the PR: an eyes reaction on the comment, a "Copilot started work" timeline event, commits that link to the session log. Context carries across sessions on the same PR. ([Using cloud agent on GitHub](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/cloud-agent/use-cloud-agent-on-github.md), [Managing agent sessions](https://docs.github.com/en/copilot/how-tos/copilot-on-github/use-copilot-agents/manage-and-track-agents.md), 2026-10-28) | The automation itself is stored separately from the repository, not in Git; the sessions it starts are visible to everyone with read access. ([Copilot automations](https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/about-automations.md), 2026-10-28) |
| **When done: handoff to a person** | Posts its review; the person applies suggestions, delegates fixes, or merges. With approvals off, a person's approval is still what the rules count. The page says to validate Copilot's feedback and add a human review. ([Code review concepts](https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/code-review.md), 2026-10-28) | When it finishes, it adds the person as reviewer (a notification follows); after a conflict fix it asks for review before merging. ([Using cloud agent on GitHub](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/cloud-agent/use-cloud-agent-on-github.md), 2026-10-28) | Opens a PR or changes made by the creator's identity; a merge by the automation: not documented (checked: Copilot automations, Creating automations). |
| **A PR it authored itself** | Reviews of PRs written by the cloud agent are billed to the human co-author, and PRs from other bots are billed to the organization and are eligible for agentic review, so such PRs can be reviewed. Copilot approving a PR it wrote itself: not documented (checked: Code review concepts, Using code review, Configuring code review). ([Code review concepts](https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/code-review.md), 2026-10-28) | Commits are authored by Copilot with the starting person as co-author. The starting person's approval does not count on the PR. ([Copilot automations](https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/about-automations.md), 2026-10-28) |

## Findings worth carrying into the lesson

- Copilot splits the PR step across separate pieces that read the same PR: code review comments, the cloud agent fixes on request,
  and automations for event triggers. Most transitions between them are a person's click or comment rather than an automatic
  hand-off. ([Using cloud agent on GitHub](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/cloud-agent/use-cloud-agent-on-github.md), 2026-10-28)
- Re-review is opt-in: one review per PR unless "Review new pushes" is on, and a re-review may repeat comments that were
  already resolved. ([Using code review](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/use-code-review.md), 2026-10-28)
- An AI approval can count, but only when switched on at three levels (public preview, off by default), and it is dismissed on the
  next push, which matches the lesson's "a patch makes the old review stale" idea.
  ([Using code review](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/use-code-review.md), 2026-10-28)
- Merge conflicts and review comments have documented fix paths; red CI has one via the failing-run page, and a Copilot push does
  not start workflows until a person approves them (unless an admin turns that off).
  ([Using cloud agent on GitHub](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/cloud-agent/use-cloud-agent-on-github.md), 2026-10-28)
- Numeric caps on rounds are not in their docs on any page checked; the one documented limit is a 59-minute session.
  ([Copilot on GitHub](https://docs.github.com/en/copilot/concepts/copilot-surfaces/copilot-on-github.md), 2026-10-28)
- Compared with the 2026-10-23 notes: approvals, the re-review setting and the merge-conflict path were not captured in the field
  and verify grids and are new here.
