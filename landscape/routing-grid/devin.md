# Devin: lesson 4 PR routing grid

Scope: lesson 4 only, the step after a PR is open: what triggers a review, when it runs again, who may approve, whether the
product fixes its own PR, what limits exist, how the next action is chosen, where PR state lives, and the handoff to a
person. Left out on purpose: how plans are made, how tickets are picked, and how checks run before the PR (lessons 1 to 3).
Every filled cell is a paraphrase of a first-party docs.devin.ai page, with its URL and the date I fetched it
(**2026-10-28**). The review and fix notes in `landscape/field-grid/devin.md` (2026-10-13) and
`landscape/verify-grid/devin.md` (2026-10-23) were a starting list; every page used here was fetched again.

Names are Devin's own, not canonical. A cell says `not documented` only after naming the pages checked.

Method: fetched the docs index (https://docs.devin.ai/llms.txt, 2026-10-28), listed the pages that could touch PR review,
auto-fix, bot comments, GitHub, stacked PRs, templates, automations or post-PR work, and fetched each as a raw-Markdown URL
(see "Pages read"). Honest limit: the fetch tool returns a condensed answer to a question I ask per page, not the raw page,
so a "not documented" answer rests on that tool saying the page lacked the topic. I did not read any page character by
character.

## The grid

(event triggers), **Stacked PRs**.

## Findings worth carrying into the lesson

- Review and approval are separate: per the page Devin Review posts findings and leaves approval to people; a beta Autoapprover exists and, per the page, will not approve a PR under its own identity. ([Devin Review](https://docs.devin.ai/work-with-devin/devin-review.md), 2026-10-28)
- Re-review is a setting ("Every push" versus once), and the only documented cap is spend per PR, not rounds. (checked pages: see the cells above.)
- Fixing its own PR works through the session that owns it; the bot-comment default and Devin's own bot identity interact, so the fix loop depends on a setting. ([Bot comment settings](https://docs.devin.ai/product-guides/bot-comment-settings.md), 2026-10-28)
- Merge-conflict repair for single PRs is not in their docs; it is documented only for stacks.
